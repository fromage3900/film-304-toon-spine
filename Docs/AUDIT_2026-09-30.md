## Read this before editing any asset

`Python/spine_lib.py` states the repo's core rule: **every material and material
function here is generated by a script, never copied as a `.uasset`.** The
reasons are recorded in that docstring, including a 2026-09-29 failure where a
cross-project rename silently truncated the master (751,265 → 666,458 bytes, all
10 `MaterialFunctionCall` references dropped, and the verifier still reported
`clean:true` because it counted zero calls).

Consequences:

- The **source of truth is `Python/`**, not `Content/`. Do not hand-edit assets
  and expect the change to survive a rebuild.
- Entry points: `Python/build_spine.py` (functions → master → outline → profiles
  → instances) and `Python/build_test_level.py` (lookdev level).
- Both write their pass/fail report to a JSON file in `%TEMP%`. **Assert on the
  report file, not on log output** — the scripts explain why.

## Findings

### F1 — The lookdev level expects World Partition externals that are not committed **[EDITOR]** — HIGH

`Content/Maps/L_Toon_Lookdev.umap` internally references
`/Game/__ExternalActors__/Maps/L_Toon_Lookdev/A/DK/MEU0CIRDQGAYMGVWZ9X3I6`.

- `.gitignore:31` ignores `Content/__ExternalActors__/`
- `git ls-files 'Content/__ExternalActors__/**'` → **0 files**

The ignore comment says these are "regenerated with the .umap". They are not:
for a World Partition level the external actor packages *are* the actor data. A
fresh clone therefore cannot contain those actors, so the level should be
expected to open incomplete or report missing packages.

**Fix (pick one):**
1. In the level: `World Settings → World Partition → Use External Actors = false`,
   save, commit the updated `.umap`; or
2. Track the folders: drop those two lines from `.gitignore` and commit
   `Content/__ExternalActors__/` + `Content/__ExternalObjects__/`.

### F2 — Stray `Content/Maps.umap` (package `/Game/Maps`) committed in the last commit — HIGH

| Evidence | Value |
|---|---|
| Internal package path in the binary | `/Game/Maps.Maps` |
| Size / commit | 30.6 KB, added by `3df13b2` (`git log --name-status -- Content/Maps.umap`) |
| Contents | references 8 of the `MI_Toon_*` instances — i.e. it is the populated lookdev level |

The package `/Game/Maps` collides with the `/Game/Maps/` folder namespace, and
the file is a duplicate of the lookdev level saved at the wrong path.

**Cause:** `Python/build_test_level.py::_new_map()` calls
`unreal.EditorLevelLibrary.new_level(MAP_DIR)`, passing the **folder**
`/Game/Maps` instead of a level path. The script then also saves correctly to
`/Game/Maps/L_Toon_Lookdev` — hence two maps.

**Fix:** delete `Content/Maps.umap`, and pass a full level path to `new_level()`
(the module already computes one as `lib.asset_path(MAP_DIR, LEVEL_NAME)`), or
pass no path at all and rely on the existing `_save_map()` call.

### F3 — `Docs/TOON_SPINE.md` documents the source project, not this repo — MEDIUM

**Fix:** rewrite the dependency graph and the toon-profile list from the current
tree (or generate them), and delete the "STRIP FOR FILM" section — the strip is
done.

### F4 — README quick-start step 2 is broken — MEDIUM

`Python/extract_dependencies.py`:

- `MASTER_PATH = "/Game/EnvSandbox/Materials/Masters/M_Master_Toon_Universal"`
  — the source project's path. In this project it resolves to nothing, so the
  script records `load_failed` for the root it is supposed to trace.
- `REPORT_PATH = Path(__file__).resolve().parents[2] / "Saved" / …` —
  `parents[2]` from `<repo>/Python/<file>` is the **drive root**, so it writes
  `P:\Saved\DependencyMap.json`, outside the repo. Should be `parents[1]`.

**Fix:** point `MASTER_PATH` at `/Game/Materials/Masters/M_Master_Toon_Universal`
and correct the `parents` index.

### F5 — README points at a builder that cannot run — MEDIUM

README lists `Python/build_master.py` as "Rebuilds the master from scratch". That
file does `import material_lib as lib`, and **there is no `material_lib.py` in
this repo** (only `spine_lib.py`) → `ModuleNotFoundError` on import. Its
docstring also points at `C:/EnvironmentPortfolio/melodia-toon-film/...`, a path
that does not exist here. The live builder is `build_master_toon.py`, invoked by
`build_spine.py`.

**Fix:** retire `build_master.py` or rewrite its imports, and fix the README
structure block — which also omits `Python/spine_lib.py`, the other
`build_*.py` scripts, `Content/Materials/Instances/` and `Content/Maps/`.

### F6 — `MF_ProceduralPatterns` appears to be wired to nothing — LOW **[EDITOR]**

The binary scan of `M_Master_Toon_Universal.uasset` shows references to
`MF_ColorRamp3` and `MF_RampLUT` only, and `build_spine.py` builds the master
with `expected_calls=["MF_ColorRamp3", "MF_RampLUT"]`. So the 41 KB
`MF_ProceduralPatterns` — the largest function in the repo — is currently not
consumed by the master or by any material instance.

Caveat, deliberately: **a text/binary scan can confirm presence, never
absence.** Close this with the asset registry (find-references on the function)
in the editor pass rather than trusting the scan.

### F7 — Repo hygiene gaps — LOW

- **No `.gitattributes`.** `.uasset` / `.umap` are binary; two people editing the
  same asset produces an unmergeable conflict with no LFS or diff protection.
  A ready-made template for this repo layout exists in the sibling Melodia
  workspace at `Humber_FinalYear_Prep/TEMPLATE_gitattributes_for_new_capstone_repo.txt`.
- **No LICENSE**, no CI workflow.
- Generated HLOD data is tracked
  (`Content/Maps/L_Toon_Lookdev_HLOD0_Instancing.uasset`) while its sibling
  externals are ignored — pick one policy.
- `Config/DefaultEngine.ini` ships an `[/Script/AndroidFileServerEditor...]`
  block with a hardcoded `SecurityToken`, for a plugin that is not enabled in the
  `.uproject`. Harmless, but it is dead config plus a token in a public repo:
  delete the block.

### F8 — Possible dangling reference in the lookdev level — LOW **[EDITOR]**

`L_Toon_Lookdev.umap` references `/Game/Maps/2kmTemplate`, which is not in this
repo — most likely the template the level was created from. Expect a
missing-reference warning on first open; clear it in World Settings / World
Partition setup.
