## Part 2 — Material wiring plan

Order matters; each step's precondition is the previous step's output.

### Step 0 — freeze a single writer

Pick ONE repo to author the wiring in. **Recommended: P:**, because the live editor is already
bound to `p:\film-304-toon-spine` (`proxy(status).worktree_root`, editor pid 16068) and the
texture import must run inside that editor. D: then receives a copy, exactly as it did for the
character profiles.

### Step 1 — land the 5 unpushed commits first

P: is carrying 111 files of unreviewed work. Wiring new material changes on top of an unpushed
base means one bad `git reset` loses both. **Requires explicit owner go-ahead plus a written
plan, per the pipeline law.**

### Step 2 — move the maps to the editor's drive

70 PNGs, 30.8 MB, `D:\film-304-toon-spine\Saved\PBR\` → `P:\film-304-toon-spine\Saved\PBR\`.
Plain file copy. No LFS involved; `Saved/` stays ignored.

### Step 3 — import as `Texture2D`

Target `/Game/Materials/Textures/PBR/<surface>/` — a subfolder, so it cannot collide with the 9
existing hatch/ramp/dither textures. Per map type:

| Map | sRGB | Compression |
|---|---|---|
| albedo `_D` | on | default |
| normal `_N` | **off** | `TC_NORMALMAP` |
| roughness `_R` | **off** | default (linear) |
| metallic `_M` | **off** | default (linear) |
| AO `_AO` | **off** | default (linear) |

Rule inherited from `build_textures.py`: **an unresolved enum is a hard build failure, not a
skip** — enum member names move between engine builds, and a silently-skipped setting is how
`T_Dither_Bayer` nearly shipped with block compression that would have destroyed the 16-level
matrix.

### Step 4 — wire `MF_PBRDetail` into the master

Measured now: `MF_PBRDetail` has `dependents: []` and `referenced_by: []` — a pure orphan, the

## Part 3 — Making the MF system unique: boil, dither, noise, film

### 3.0 What already exists, measured

| Asset | Measured state |
|---|---|
| `MF_ProceduralPatterns` | 464 expressions; 12 pattern fields (Halftone, Checker, Stripes, Crackle, InkSplat, CrossHatch, Stipple, Rings + Voronoi, Grid, Perforation, Weave) |
| `T_Dither_Bayer` | 64×64, `TF_Nearest`, `mip_count 1`, `TC_VectorDisplacementmap`, `TA_Wrap` |
| `T_Noise_White` | 64×64, `TF_Bilinear`, `mip_count 7` — **white** noise |
| `M_Outline_InvertedHull` | inverted-hull; `MI_Outline_Thin` / `_Heavy` |
| Post-process material | **none** |
| PostProcessVolume in any map | **none** (`grep -a PostProcessVolume Content/Maps/*.umap` → empty) |
| `Config/DefaultEngine.ini` | `r.Substrate=True`, `r.Substrate.OpaqueMaterialRoughRefraction=False` — no grain/tonemap/OCIO keys |

So the boil / dither / noise / film lane is **greenfield**. That is the opportunity.

### 3.1 The architectural caution, first

`Docs/FILM_PIPELINE.md` warns, and this repo's whole design rests on it: *"No post-process
fighting — old post-process cel shading quantizes finished pixels in screen space, can't
distinguish materials, and fights fog/bloom/translucency."*

That is why this film uses Substrate Toon, where banding is part of how the material responds to
lights. **A film-emulation post-process stack must not re-introduce the thing Substrate Toon was
chosen to avoid.** Concretely: film grain, halation and misregistration are *finishing* effects
applied after shading — they are additive and safe. Anything that re-quantizes luminance
(a post-process cel/toon pass) is not, and would put a second terminator authority in the film.

The rule to carry: **surface MFs own shading; post-process owns finishing. No post-process pass
may re-derive the band.**

### 3.2 `MF_Boil` — the animation boil

**What it is.** "Line boil" is the shimmer hand-drawn lines have frame to frame, because every
frame is re-inked by hand. Reproducing it deliberately is what makes CG read as drawn.

**The researched constraint — boil must be quantized, not smooth.** From the Spider-Verse
production account: *"The majority of the animation is done in twos instead of ones (images are
held for two frames, rather than one – or twelve images per second, instead of twenty-four)"* and
*"we could never get the look of the animation right when it was too splined or too smooth …
step down animation to allow animation to hold poses."* (fxguide, *Why Spider-Verse has the most
inventive visuals you'll see this year*, 2018-12-17.)

A smooth sine wobble reads as *swimming CG*, not as drawn animation. The offset must **hold** for
2–3 frames then jump.

**Construction.**

```
Time  -> floor(Time * Fps) * (1/Fps)        quantize to 12 fps (twos) or 8 fps (threes)
      -> hash(quantized_time + ObjectRandomSeed)   per-object decorrelated offset
      -> offset  (float2, small, e.g. +/- 0.0015 UV)
```

Inputs: `Fps` (12.0 = twos, 8.0 = threes), `BoilAmount`, `BoilSeed`, `Hold`.
Output: `BoilOffset (float2)`.

**Two implementations, because they fail differently** (the pattern Bokit ships for the same
reason):

- **Overlay material** on skeletal meshes — characters. Needs clean edge definition; avoid
  excessively dense geometry.
- **Post-process material** on static meshes — props, environment. Soft-edged objects do not
  outline correctly.

**Project settings this depends on** (Bokit's documented requirements): CustomDepth-Stencil Pass
enabled *with Stencil*; Custom Depth with TemporalAA Jitter enabled; Temporal Upsampling enabled;
AA method TAA.

> **Conflict to resolve:** TAA jitter and a 1:1 nearest-sampled dither are natural enemies — TAA
> smears the dither that §3.3 depends on. This must be prototyped before either lane is built,
> not after. It is the single biggest technical risk in this document.

**Where it plugs in.** `MF_ProceduralPatterns` already takes `UV`. `MF_Boil` should offset the
UV *before* the pattern function, so hatch lines boil with the surface instead of sliding across
it. Wire as `UV + BoilOffset` into the existing `UV` input — no new pattern fields needed.

### 3.3 `MF_Dither` — ordered and blue-noise

**What already exists and why it is limited.** `T_Dither_Bayer` is 64×64 `TF_Nearest`, `mip_count
1` — correct for a Bayer matrix (the mip/compression choices were a real fix, see
`TOON_CLOSEOUT_2026-10-02.md` §7). But two limits are structural, not bugs:

1. **A 64×64 Bayer tile repeats visibly** at 1080p. Bayer is ordered dithering: *"the pattern
   decides the texture; the pixel decides nothing about its neighbours. One comparison per
   pixel."* (Plotcaster, *Dithering algorithms compared*.) That regularity is what the eye
   catches as crosshatch structure.
2. **Blue noise is the researched upgrade.** *"Dither generated from blue noise is the least
   unsightly and distracting"* (Wikipedia, *Dither*, citing the standard halftoning literature).
   The underlying review is Ulichney, *A Review of Halftoning Techniques* (2000), and
   HPL-2003-62, *Fundamental Characteristics of Halftone Textures: Blue-Noise and Green-Noise*.

**Design.**

| Mode | Source | Trade |
|---|---|---|
| 0 — Bayer | existing `T_Dither_Bayer` | stable in animation, tiles cleanly, visible structure |
| 1 — Blue noise | **new** `T_Dither_BlueNoise` (void-and-cluster or Mitchell) | least unsightly, needs generating |
| 2 — Interleaved gradient noise | analytic, no texture | free, animated-safe, no memory |
| 3 — White noise | existing `T_Noise_White` | worst for dithering; keep only for grain |

**The critical sampling rule.** A dither must be sampled **1:1 against screen pixels**
(`SvPosition` / pixel coordinates), *not* UV. Sampled by UV it tiles across the surface and the
tile becomes the visible artifact — which is exactly the failure the 64×64 Bayer tile has today.
Screen-space sampling also makes it resolution-correct for free.

**`T_Noise_White` is the wrong texture for this lane** — white noise has visible clumps and is
bilinear-filtered with 7 mips, so it softens. It should stay a *grain* source (§3.5), not a
dither source.

### 3.4 `MF_FilmStock` — the researched print presets

These are the techniques the reference films actually used. Each becomes a named preset, not a
knob soup.

**a. Misregistration** — *the* Spider-Verse signature, and the cheapest to build. From the same
production account: *"sometimes in printing comic books, the color offsets were not aligned
properly and this looked like the image was out of focus … So, we splintered and offset the image
in a way that is similar to a misprinted comic book page. It has a really cool feel to it that
creates this illusion that something is printed on the screen."*

Construction: split the image into 3 colour passes (R / G / B), offset each by a small,
per-channel, *frame-varying* `float2`, recombine. Per-channel offsets are what reads as print;
uniform offsets read as a blur.

**b. Halation** — researched definition: *"a reddish or warm glow around bright highlights caused
by light passing through the emulsion, reflecting off the base, and scattering back into the
image. It is a stock behavior, not a diffusion filter and not flare inside the lens."*
(Melies, *Halation Film*.) Also *"light passes through the emulsion, bounces off the back of the
film, and re-exposes the image."* (fimii, *What Is Halation?*)

Construction: threshold luminance → blur → tint warm (red-orange) → add back. **Threshold first**
— halation only appears around *bright* areas; applying it to the whole image is a bloom, not
halation.

**c. Gate weave** — the small mechanical jitter of film through a projector. Same construction
family as boil, but *global* (whole frame, one offset) rather than per-object, and slower.

**d. Print density curve** — the steeper response of a print stock versus a camera negative.
*"The density curve of a negative, the steeper response of a print stock, the halation that light
produced."* (Leumos, *Film emulation in color grading*.) Kodak 2383 is the canonical reference
stock and the one most referenced in the grading literature (JVKE 2383 print LUTs; Dehancer Pro
2383; Color Finale's photochemical stock emulations).

**Deliberately NOT built:** a 2383 LUT. `Docs/FILM_PIPELINE.md` puts final colour grade in
DaVinci Resolve, and `specs/humber_toon_spine/*.json` declares the colour space as
`ACEScg / AgX Punchy`. Baking a print LUT into a shader would double-grade against the Resolve
pass. Halation, misregistration and weave belong in-engine because they are *spatial*; density
curves belong in the grade.

### 3.5 PPV plan — the finishing stack

Measured: **no PostProcessVolume exists in any map**, and no post-process material exists. This
lane is entirely unbuilt.

Per `Docs/FILM_PIPELINE.md` the film already ships `L_Toon_Lookdev`, `L_Brutalist_Layout` and
`L_Toon_Shot_Env`, and `Python/compose_shot_env_level.py` already generates level content
(sun rotation, ground plane). **PPV settings should be generated the same way** — a
`Python/build_ppv_presets.py` — not hand-placed, or they violate `CONTENT_CONVENTIONS.md` ("the
instance parameters are generated; a change made in the editor only will be lost").

Proposed preset ladder, one per narrative register:

| Preset | Misregistration | Halation | Weave | Grain | Use |
|---|---|---|---|---|---|
| `PPV_Print_Clean` | 0 | off | 0 | low | dialogue, close-ups (SH040, SH050) |
| `PPV_Print_Pulp` | high | strong | on | mid | establish / action (SH010, SH060) |
| `PPV_Print_Song` | mid | strong | slow | low | song_release, bow_finale (SH070, SH080) |

Note the tension worth flagging to the owner: SH050 `macro_emotion` is the shot the manifest
says must show *"warm-violet (#352D40) halftone shadow ramp"* legibility. A heavy finishing stack
on that shot would fight the very thing the shot exists to show. Hence `PPV_Print_Clean` as the
close-up default.

### 3.6 Build order, when it is approved

1. `MF_Boil` — smallest, unblocks the drawn feel, plugs into the existing `UV` input.
2. `T_Dither_BlueNoise` + `MF_Dither` — closes the tiling artifact in the existing Bayer path.
3. `MF_FilmStock` — misregistration first (cheapest, highest read), then halation.
4. `Python/build_ppv_presets.py` — after the MFs exist, so the presets have something to drive.

Every one of these is a new builder under `Python/`, registered in `build_spine.py`, asserting on
the report file. None of them may default to a visible change.
